# 安全提取说明

## 默认行为

`extract` 必须指定至少一个 `--path`、`--extension` 或 `--type`，且默认只输出 `dry-run` 计划。只有加入 `--execute` 才写文件。`--archive` 可进一步限制为 `MASTER.DAT` 或 `CRITTER.DAT`；路径、扩展名和类型筛选器之间按“任一匹配”选择。

输出固定为 `workspace/raw/<archive>/...`，因此不同 DAT 的同名资源不会覆盖。所有目标在规划和写入前都经过解析路径校验；含绝对路径、`..`、盘符、控制字符、Windows 保留名、文件名分隔符或尾随点/空格的条目会被拒绝。工作区解析后的真实路径必须仍位于 `workspace/`，用于阻止符号链接逃逸。

## 写入与来源保护

现有目标默认使整个批次在写入前停止。`--overwrite` 必须与 `--execute` 同时使用，并通过同目录临时文件与 `os.replace` 原子替换。规划时记录源档案大小和纳秒时间戳，执行前再次比较；源档案若发生变化立即停止。

每次成功执行会在 `workspace/manifests/` 写入独立清单，记录源档案路径、档案内路径、偏移、存储大小、解压大小、压缩模式、输出路径和输出 SHA-256。每个文件的写入是原子的，但多文件批次不是跨文件事务；若后续文件解压失败，先前成功生成的新文件会保留。

## 支持范围

- `0x20`：按原始大小直接读取。
- `0x40`：读取带符号大端块长度；负值块直接复制，正值块使用 4096 字节字典、最短匹配 3、最长匹配 18 的 LZSS。
- `0x10`：清单可识别，但本机档案未出现，提取器拒绝处理。

真实验证样本为 `TEXT/ENGLISH/DIALOG/AIRLOCK.MSG`（`0x20`）和 `TEXT/ENGLISH/DIALOG/HAROLD.MSG`（`0x40`）。重复提取在未指定覆盖时被拒绝，原输出哈希未变化。
