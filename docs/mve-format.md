# Interplay MVE 检查与预览说明

## 容器结构

Fallout 1 影片以 26 字节头开始：20 字节签名 `Interplay MVE File 1A 00`，随后是小端常量 26、256 和 `0x1133`。之后每个块由 16 位载荷大小和 16 位块类型开头；块内每段由 16 位大小、8 位操作码和 8 位版本开头。

工程内解析器遍历全部块和段，拒绝截断、段越界、异常计时、危险尺寸和无效调色板。它识别计时 `0x02`、音频初始化 `0x03`、显示缓冲 `0x07`、音频/静音 `0x08/0x09`、调色板 `0x0C/0x0D`、解码图 `0x0F` 和视频数据 `0x06/0x10/0x11`；其他操作码保留在 CSV，不执行。

`display_count` 统计 `0x07` 显示事件，`frame_count` 统计实际视频数据段。全量 13 个影片中有 6 个两者不同；FFmpeg 可解码帧数与后者一致。因此两项分别保留，不能把显示事件直接当作新视频帧。

帧间隔为计时段中 32 位 rate 与 16 位 subdivision 的乘积，单位为微秒。视频宽高以 8 像素块记录。音频标志的低三位依次表示双声道、16 位和版本 1 的 Interplay DPCM。

## 外部解码边界

MVE 的视频帧由解码图、两个历史缓冲区和 8×8 块预测操作共同重建。项目保留原生容器解析，但将像素和 DPCM 解码交给 FFmpeg。FFmpeg 官方格式表列出 Interplay MVE 解封装支持，其 `ipmovie` 解封装器与 `interplayvideo` 解码器也明确描述了解码图和视频数据的组合方式。

`convert-mve` 必须显式接收 `--ffmpeg`，同时要求同目录存在 ffprobe。工具版本、两者 SHA-256、全部同目录 DLL 及组合清单哈希写入 JSON。外部工具只写工作区临时目录；工程随后验证：

- 源探测的宽高、帧数、声道和采样率必须与原生解析一致；
- PNG 的 IHDR 必须与源尺寸一致；
- WAV 必须是匹配源声道与采样率的 16 位 PCM；
- MP4 的宽高与解码帧数必须和源一致。

MP4 使用 MPEG-4 Part 2 与 AAC，仅作便捷预览，不视为保存格式。源 MVE、首帧 PNG、PCM WAV、段 CSV 和全部哈希共同提供追溯依据。

`convert-mve-batch` 按来源隔离输出，逐文件记录成功或失败。复跑会重新解析源容器，并核对转换器版本、固定 FFmpeg 工具链哈希、JSON 校验和及全部派生文件 SHA-256；不一致时必须显式使用 `--overwrite`。
