# 统一资源索引

## 当前范围

索引器读取 `workspace/manifests/inventory.json`、全部 extraction manifests 和 `workspace/output/` 中受支持的转换元数据。它不重新提取或转换资源。输出包含来源资源身份、提取状态、派生文件、冲突、失败和输入批次信息。

`resource_id` 对 `source_kind`、`source_name` 与原始 `internal_path` 的 UTF-8 规范串计算 SHA-256，因此不依赖本机绝对路径。`normalized_path` 仅用于发现 Windows 大小写冲突，不作为资源身份。

## 输出

- `resources.jsonl`：每行一个来源资源；无冲突的唯一来源标为有效，冲突候选保持 `null`。
- `derived.jsonl`：每行一个实际派生文件，含反向资源 ID、角色、路径、大小、哈希、生成器和校验状态。
- `failures.jsonl`：每行一个可定位的失败或陈旧原因；当前无异常时为空文件。
- `collisions.csv`：每行一个规范化冲突路径，候选来源保存在 `candidates_json`，便于完整保留大小写和来源字段。
- `summary.json`：批次 ID、全部输入哈希、资源类型、来源、状态、冲突和失败计数。
- `index.json.sha256`：上述五个索引文件的 SHA-256，用于重复运行校验。

命令默认 dry-run。执行时先在索引目录旁构建完整临时目录；所有文件成功写入后再切换为正式目录。索引目录中出现非受管理文件时，即使指定覆盖也会停止，避免删除用户文件。

## 状态与恢复

提取结果只有在相对路径、大小和 SHA-256 与实际文件一致时才标为 `extracted`。转换源、元数据校验文件及元数据内声明的派生哈希也会复核；不一致项标为 `stale` 并写入 `failures.jsonl`。同一资源跨批次重复出现时，核心字段必须一致，较旧清单的空偏移字段可由新清单补齐。

批次 ID 是 inventory、提取清单、转换元数据、索引 schema 和程序版本的内容摘要，不使用运行时间。同一输入得到同一批次 ID；输入变化才产生新批次。每次执行先在临时目录构建整套文件，再切换正式目录，中断不会覆盖上一套完整索引。

来源优先级仍待人工决策。`not_selected` 只表示尚未提取或转换，不能解释为资源不存在或处理失败。
