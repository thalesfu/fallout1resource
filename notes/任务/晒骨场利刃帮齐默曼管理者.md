## 写入点

- `RAZOR`：`Razor33` 仅在 614 == 9202 时出现，选项 34→9104、35→9103、36→9102（36 需 612 != 9003）。`Razor16` 用 `create_object_sid(238)` 给出磁盘。
- `JON`：`Zim26`（放磁盘，需持有 238）→ 612 = 9003；若此时 613 == 9102 则 613 = 9103。`critter_p_proc`：613 == 9103 且 612 != 9003 时攻击玩家；`Start` 在 9103 时按 612 把自己分到 89 队（管理者）或 0 队（玩家）。
- `PGUARD`（齐默曼贴身卫兵，proto 257）：`timed_event_p_proc` 中 612 == 9003 或 613 == 9103 → `float_msg`“老头，我想我们不需要你了”（REGULATR.MSG 139）并 `attack(JonPtr)`。
- `ADYTOWNR`（居民）：613 ∈ {9102, 9103} 时 `critter_add_trait(self, 1, 6, 0)` 改为 0 队（玩家阵营），否则 49 队。
- `REGGUARD`：613 == 9103 时设 616 = 1 并攻击玩家；地图变量 M[1] 计数存活管理者。
- `LAADYTUM`（地图脚本）：
  - 9103 且 M[2]==0 且 GVAR 266==1 → `AddInBlades` 刷出利刃帮。
  - **9104 且 M[2]==0** → `gfade`，`kill_critter_type` 处死 proto 3/27/36/112/215/244–263（全部管理者、卡勒布、狗、治安官格瑞），613 = 2，声望 +2，`give_exp_points(2000)`。
  - M[1]==0 且 613 == 9103 → 613 = 2，352 = 1，声望 +2，2000 经验。

## 结论

- 9104 是唯一不打地图战的路线，居民不会被卷入。
- 管理者（含贴身卫兵）死后再给齐默曼放磁盘，PGUARD 已死，不会冲突，得到“管理者已除 + 齐默曼知道真相 + 利刃帮与内城区和平”。
- 9102 状态下只要还没给齐默曼放磁盘，回去找剃刀仍会走 `Razor33`，可改选 9104。
- 结局幻灯片（`endgame.cc`）晒骨场只看 `FOLLOWERS_INVADED` / `TRAIN_FOLLOWERS`，与此无关。

## 更正 2（2026-09-30）：齐默曼的第三条敌对判定

`JON.critter_p_proc` 实际有三段（按字节码顺序）：

1. 看得见玩家时：`613 == 9103 && 612 != 9003` → `critter_add_trait(self,1,6,89)`（改到管理者队）+ 喊 288:174「你这个杂种！你把魔鬼带进了我的家门！」+ `attack(dude)`；
2. 否则 `251 == 1`（内城区居民敌对）→ `attack(dude)`；
3. **偏移 3842 起，脱离“看得见玩家”分支：`616 == 1` → 改到 89 队 + `attack(dude)`，没有任何 612 豁免。**

`616` 由 `REGULATR` / `REGGUARD` / `PGUARD` / `CALEB` 四类脚本的 `damage_p_proc`、`destroy_p_proc`、`pickup_p_proc` 在来源是玩家时置 1。

因此上一版笔记里“自己清光管理者可以保住齐默曼的善意”是错的：**玩家只要亲手伤到任何管理者，齐默曼必定翻脸**，即使已经听过磁盘。用户实测（在内城区攻击守卫后齐默曼立刻敌对）印证了这一点。

唯一能让齐默曼活着且不敌对的路线：先放磁盘（612 = 9003）→ 选 9103 开战 → **玩家全程不攻击管理者**，由 8 名利刃帮清场（击杀来源不是玩家，616 保持 0）。代价是居民照样会在混战中被打死，且齐默曼此时属于玩家队伍会参战，有战死风险。

- `JON.damage_p_proc` / `destroy_p_proc`：`source_obj == dude` 且 **`616 != 1`** 时才置 `251 = 1`。因此在管理者已敌对（616 = 1）的局面下打死齐默曼，不会连带引发内城区居民敌对。
- 存档核对手法：死亡 critter 的 `script_id` 会被清成 -1、`script_filename` 变空，所以统计存活数要按**原始地图的对象 ID 集合**去比对存档对象，不能按脚本名过滤。
- `scripts/annotate_map_targets.py` 新增 `--save-map`：读取 `SLOTnn/<MAP>.SAV` 的实时位置与存活状态，只标注幸存目标；画布坐标由 `hex_tile_screen_position(tile) + canvas_translation`，再对人物锚点偏移补 −50 像素。
