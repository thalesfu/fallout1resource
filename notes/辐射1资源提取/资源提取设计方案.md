## 目标与范围

建立一个可重复、可核验的通用资源提取工程，从《辐射 1》安装包中整理档案目录，并按需提取文本、脚本、地图、原型、图像、声音、动画及索引文件。工程同时保存原始字节、转换产物和来源信息，便于后续制作对话树、地图资料、人物图鉴或数据表。

工程已完成只读清单、安全小样本提取、MSG 转换、INT 反汇编、FRM/PAL 图像转换、MAP/PRO/LST 结构化、ACM 音频和 MVE 动画预览里程碑，尚未执行全量解包。存档目录 `DATA/SAVEGAME/` 默认排除；若以后研究存档，应另建任务，避免混入游戏静态资源。具体实施顺序见 [[工作计划 Checklist]]。

## 不损坏源文件的原则

游戏目录 `C:\Program Files (x86)\Steam\steamapps\common\Fallout` 只作为只读来源。任何工具的输入都必须是代码工程内的普通副本，输出也只能位于代码工程的本地工作区；禁止在游戏目录中解包、转换、改名或覆盖文件，也不使用硬链接。

## 存放位置与职责

提取程序、测试、工程配置、工具记录和本地工作区统一放在独立 Git 工程：

`C:\Users\Thales\codes\github.com\thalesfu\fallout1resource`

建议结构如下：

```text
fallout1resource/
├─ README.md
├─ AGENTS.md
├─ docs/                  # 格式说明、工具评估、开发文档
├─ src/                   # 提取、转换和索引程序
├─ tests/                 # 单元测试与小型测试样本
├─ config/                # 排除规则和示例配置，不写死本机路径
└─ workspace/             # 本地数据区，整体不提交 Git
   ├─ input/              # DAT 或选定松散文件的只读副本
   ├─ raw/                # 保持档案内路径和原始字节
   ├─ cache/              # 可重新生成的中间文件
   ├─ manifests/          # 路径、大小、哈希和来源清单
   ├─ output/             # 文本、地图、图像、音频等派生物
   └─ logs/               # 命令、工具版本、警告和校验结果
```

Obsidian 的 `工程/辐射1资源提取/` 只保存设计方案、Checklist、研究结论和面向笔记的最终索引，不存放 DAT 副本、解包文件、第三方可执行工具或大体积转换产物。`workspace/`、游戏资源和可能受版权保护的派生文件必须加入 `.gitignore`，不得推送到 GitHub。

## 资源分类与处理路线

| 类型 | 常见格式 | 处理方式 | 派生产物示例 |
|---|---|---|---|
| 资源档案 | `.DAT` | 使用明确支持 Fallout 1 DAT1 的工具列目录、按路径提取 | 原始目录树、清单 |
| 文本与对话 | `.MSG` | 检测并记录原编码，保留全部编号出现项及最后生效语义 | UTF-8 JSON/CSV、对话文本 |
| 编译脚本 | `.INT` | 只读解析过程表和栈式字节码，关联同名 MSG；不执行脚本 | 结构化反汇编、消息引用、对话边 |
| 地图与对象 | `.MAP`、`.PRO`、`.LST` | 解析地图、原型和列表索引；列表顺序不可改变 | JSON/CSV、地图对象表 |
| 图像与调色板 | `.FRM`、`.PAL` | 使用对应调色板转换，保留方向、帧和偏移信息 | PNG、帧元数据 |
| 声音与动画 | `.ACM`、`.MVE` | ACM 由纯 Python 解码；MVE 先由工程解析容器，再以固定版本与哈希的 FFmpeg 解码 | WAV、PNG、段清单、预览 MP4 |

原始提取层永不接受转换器写入；所有 PNG、JSON、CSV、WAV 等均进入 `fallout1resource/workspace/output/`，并通过清单反向指向源档案、档案内路径和 SHA-256。

## 实施流程

1. **盘点来源**：记录游戏版本、安装目录、两个 DAT 的哈希，并分别清点 DAT 与 `DATA/` 中的松散文件；排除 `SAVEGAME/`。
2. **验证工具**：优先选择能只列目录和单文件提取的 DAT1 工具。每个工具记录来源、版本、哈希、命令参数和支持格式，不把工具安装进游戏目录。
3. **准备副本**：只复制当前批次需要的档案或文件到代码工程的 `workspace/input/`，复制后比对哈希并设置只读。空间不足时按档案分批处理。
4. **原样提取**：先生成档案清单，再按资源类别提取到 `workspace/raw/`。禁止路径穿越、绝对路径输出和覆盖同名文件；冲突文件按来源分层保存。
5. **分类转换**：每类格式使用独立转换步骤。转换失败不得修改或删除原始提取文件，并将错误写入日志。
6. **建立索引**：输出统一清单，至少包含 `source_archive`、`internal_path`、`size`、`sha256`、`type`、`derived_files` 和 `tool_version`。
7. **抽样核验**：每类至少检查一个代表文件。例如用 `HAROLD.INT` 与 `HAROLD.MSG` 验证脚本—文本关联，但它只是测试样本。
8. **收尾校验**：再次核对安装目录中的核心档案哈希，确认未发生写入；再由用户决定是否把研究结果链接到 Obsidian 正式笔记。

## 验收与回退

- 核心档案的大小、时间戳和 SHA-256 与操作前一致。
- 任一派生文件都能追溯到唯一来源；不同档案或松散目录中的同名文件不会互相覆盖。
- `.LST` 的顺序、`.MSG` 的编号与编码、`.FRM` 的帧方向和偏移均有保留。
- 解包器必须阻止 `..`、盘符路径等越界写入；不符合要求的工具不得使用。
- 所有生成物均局限于 `fallout1resource/workspace/`。回退时只处理该本地工作区，绝不以工程副本反向覆盖游戏目录。
