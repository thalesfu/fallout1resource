# 安全运行手册

关联：[[项目导航]] · [[资源提取设计方案]] · [[经验总结与待决策]]

## 会话准备

在 PowerShell 中进入代码工程后设置本次会话变量。路径只作为示例；不要把本机路径写入可提交配置。

```powershell
$repo = "C:\Users\Thales\codes\github.com\thalesfu\fallout1resource"
$game = "C:\Program Files (x86)\Steam\steamapps\common\Fallout"
$python = "C:\Users\Thales\.cache\codex-runtimes\codex-primary-runtime\dependencies\python\python.exe"
Set-Location $repo
$env:PYTHONPATH = "$repo\src"
```

开始前检查：

```powershell
git status --short
Get-FileHash "$game\MASTER.DAT", "$game\CRITTER.DAT" -Algorithm SHA256
& $python -m unittest discover -s tests -v
```

若 DAT 哈希与 [[项目导航#固定基线]] 不同，应先确认游戏版本、补丁或文件损坏，不继续批处理。

## 标准操作顺序

### 1. 重新盘点

```powershell
& $python -m fallout1resource inventory `
  --game-dir $game `
  --workspace "$repo\workspace"
```

清单进入 `workspace/manifests/`。盘点不解包；`DATA/SAVEGAME/` 默认排除。

### 2. 先规划提取

```powershell
& $python -m fallout1resource extract `
  --game-dir $game `
  --workspace "$repo\workspace" `
  --archive MASTER.DAT `
  --path "TEXT/ENGLISH/DIALOG/HAROLD.MSG"
```

核对来源档案、内部路径、大小、压缩模式和目标路径。确认后只增加 `--execute`，不要同时临时更改筛选条件。已有文件默认停止；只有确认目标可替换时才使用 `--overwrite`。

### 3. 转换也先 dry-run

| 格式 | 命令 | 关键额外参数 |
|---|---|---|
| MSG | `convert-msg` | 不确定编码时显式 `--encoding` |
| INT | `disassemble-int` | 可传同名 `--msg` 与 `--msg-encoding` |
| FRM | `convert-frm` | 必须指定 `--palette` |
| MAP | `convert-map` | 必须指定 `--prototype-root`，建议传 `--scripts-lst` |
| ACM | `convert-acm` | 无额外运行依赖 |
| MVE | `convert-mve` | 执行时必须显式 `--ffmpeg` |

示例：

```powershell
& $python -m fallout1resource convert-acm `
  --input "$repo\workspace\raw\master\SOUND\SPEECH\HARLD\HROLD1.ACM" `
  --workspace "$repo\workspace"
```

检查摘要和全部目标路径后增加 `--execute`。MVE 使用的固定工具包、哈希和许可证边界见代码工程 `config/ffmpeg-mve.json`；不要自动采用 `PATH` 中版本不明的 FFmpeg。

## 每批完成后的检查

```powershell
& $python -m unittest discover -s tests -v
Get-FileHash "$game\MASTER.DAT", "$game\CRITTER.DAT" -Algorithm SHA256
git status --short
```

同时检查：

- 产物位于 `workspace/output/`，原始提取物位于 `workspace/raw/`。
- JSON 中有源路径、源 SHA-256、工具版本和派生文件哈希。
- Git 没有 DAT、ACM、MVE、PNG、WAV、MP4 或其他游戏资源。
- 代表性 PNG/视频需要目视抽查，WAV 需要实际试听；结构校验不能代替人的内容判断。

## 必须停止的情况

- 源 DAT 哈希变化，或规划后源文件大小/时间戳变化。
- dry-run 目标不在 `workspace/`，来源层级不明确，或同名覆盖关系不清楚。
- 解析器报告截断、未知压缩模式、计数/偏移冲突或编码置信度不足。
- 批次需要 `--overwrite`，但没有确认现有产物是否仍需保留。
- 外部工具版本、许可证或哈希无法复核。

## 失败后的恢复

不要修改 `workspace/raw/` 中已核验的原始字节。先保留错误和对应清单，再修复程序或缩小批次；输出命令默认拒绝覆盖，因此失败后可检查哪些目标已存在。若需要重跑，逐个核对目标后显式覆盖。绝不把工程文件反向复制到游戏安装目录。

若桌面工具显示命令超时，先检查对应 Python 子进程是否仍在运行；外层超时不保证子进程已经退出。不要立刻启动第二份全量索引。确认 PID、父进程、启动时间和命令行后，只停止确定属于旧批次的进程，再保留当前批次继续。
