# 人物文档建立方法

本文总结《辐射 1》人物笔记的建立方法。[[Hub 哈勃城 - Harold 哈罗德（ID 1633）|Harold 哈罗德]]是第一篇完整实例；具体人物可以因素材量不同增减叙事小节，但身份、地图对象、形象、游戏数据、物品和可发生的对话必须遵循同一套证据规则。

## 基本原则

1. 一篇笔记对应一个地图中的人物对象，不按人物类别合并。
2. 地图对象必须用“地图名 + 楼层 + 地图对象 ID”唯一确定。
3. 人名优先采用素材中可以直接确认的英文名和中文名；素材只给名字时，不补造姓氏。
4. 对话、观察文字和传闻保留当前游戏素材的实际内容，不擅自润色成新的台词。
5. 游戏中的直接陈述、人物自己的说法、其他人物评价和整理者推断必须分开。
6. 技术过程留在“工程”和资源仓库中；人物笔记只保留理解人物、剧情和游戏表现所需的数据。

## 资源取值顺序

| 顺序 | 资源 | 主要用途 |
|---:|---|---|
| 1 | 地图对象记录 | 地图对象 ID、楼层、地图格、坐标、朝向、当前生命值、库存、人物脚本。 |
| 2 | 人物原型 | 人物原型 ID、英文原型名、形象 FRM、SPECIAL、战斗数据、技术年龄和性别。 |
| 3 | 当前中文消息资源 | 观察文字、玩家选项、人物原话、动态台词和关键词回答。 |
| 4 | 脚本反汇编与消息引用表 | 对话入口、选项跳转、条件分支、随机台词范围、交易或任务状态。 |
| 5 | 同地图其他人物的直接台词 | 身份、关系、职业、任务作用和称呼。 |
| 6 | 已确认的地点与任务资料 | 人物在区域、任务链和商店服务中的位置。 |

同一编号存在多条消息时，使用当前资源中标记为 `effective` 的最终文本。英文原文与中文覆盖同时存在时，正文采用当前中文文本；只有中文资源确实缺失时才保留英文并明确说明。

## 对象与名称核对

### 地图对象 ID

文件名中的 `ID` 一律指地图对象 ID，不是人物原型 ID 或脚本 ID。普通人物即使名称、原型和脚本完全相同，也要逐对象建立笔记。

### 专名人物

专名应由以下至少一项直接确认：

- 专用人物脚本或观察文字；
- 人物原型名称；
- 人物自我介绍；
- 其他人物明确点名，且能通过人物原型或地图位置落到唯一对象。

素材只提供 `Harold`、`Vance`、`Slappy`、`Rutger`、`Vinnie`、`Justin` 或 `Chad` 时，“全名”写明素材没有提供姓氏。不能把同名角色的姓氏移植过来。

### 普通人物

`Police`、`Merchant`、`Peasant`、`Boy` 等是类别名，不当作专名。文件名仍采用英文类别名 + 中文类别名 + 地图对象 ID；别名也必须保留 ID，避免多个同名页面发生歧义。

## 文件名与属性

文件名格式：

```text
地点英文名 中文名 - 英文人物名 中文人物名（ID 地图对象ID）.md
```

基础属性：

```yaml
---
title: 英文人物名 中文人物名（ID 地图对象ID）
aliases:
  - 地点英文名 中文名 - 英文人物名 中文人物名
tags:
  - 辐射1
  - 人物
  - 地点
  - 区域
map: 地图资源名
elevation: 楼层
map_object_id: 地图对象ID
prototype_id: 人物原型ID
map_tile: 地图格
resource_script: 人物脚本.INT
---
```

没有独立人物脚本时不伪造 `resource_script`。专名人物可以设置不带 ID 的别名；普通同名人物只设置带 ID 的别名。

## 标题结构

### 固定一级标题

每篇人物笔记至少包含：

1. 名称
2. 地图信息
3. 形象
4. 游戏数据
5. 物品信息
6. 身份与处境

### 条件一级标题

只有素材存在相应内容时才增加：

- 商店与服务
- 可以谈论的主题
- 对话
- 生平
- 性格与言行
- 他人评价
- 掌握的信息
- 任务关联
- 未确定的信息

不为保持形式而建立空标题。普通人物没有生平或专属剧情时，应简短而完整，不把共用脚本的随机台词扩写成个人经历。

## 名称

名称表记录英文名、中文名、全名判断和游戏观察文字。观察文字优先采用人物脚本的 `look_at_p_proc`；没有覆盖时使用人物原型描述。

人物原型名和脚本观察文字可能冲突。例如人物原型是 `Merchant`，共用脚本却显示“你看到一个瘾君子”。两项都应保留并说明来源，不能为了整齐而删除冲突。

## 地图信息

### 人物位置图

地图信息标题下先放人物位置图，再放表格。位置图规则见[[人物位置图生成与裁切规范]]：

- 所有其他人物使用绿色轮廓、引线和标签；
- 当前人物按地图对象 ID 选中，使用橙色；
- 不绘制物品、容器或物品标签；
- 裁切到人物可活动的区域，但保留所有人物标签；
- 缺失人物 FRM 时只高亮坐标锚点和标签，不借用其他人物形象。

普通同名人物必须依靠橙色焦点和地图对象 ID 区分，不能按显示名匹配。

### 地图表格

表格至少记录：出现地点、资源地图、楼层、地图对象 ID、人物原型 ID、地图格、地图坐标、朝向、人物脚本和人物形象。

## 形象

### 地图人物精灵

地图人物精灵采用地图对象实际使用的 FRM、朝向和第0帧。不能只按人物原型默认朝向取图。

### 对话头像

只有导出数据确实关联 HEADS 资源时，才加入静态头像、表情和动画。检查时不能只看人物原型的 `head_fid`：若人物脚本调用 `start_gdialog`，应读取其头像索引参数，再按 `ART/HEADS/HEADS.LST` 的零基索引反查头像前缀。例如德克脚本使用索引 7，对应 `DEKKR`；即使原型的 `head_fid` 为 `-1`，也不能据此判定没有头像。没有独立对话头像的人物只保留地图精灵。

确认头像前缀后，从中性第一组动画的第 0 帧制作静态大头像；有对应素材时，再加入友好、中性、敌对表情，以及待机、口型和状态转换动画。动画使用资源元数据中的有效帧率，按导出原始帧播放，不补帧或重绘。

## 游戏数据

### SPECIAL

SPECIAL 直接取人物原型的基础属性：力量、感知、耐力、魅力、智力、敏捷、幸运。

### 其他数据

优先记录当前生命值、行动点、护甲等级、近战伤害、最大负重、顺序、治疗率、暴击率、辐射抗性、毒素抗性、击杀经验值、AI 包和队伍。

地图当前值与人物原型值冲突时，以不同名称分别记录。人物原型中的年龄和性别属于技术字段；若与剧情明显矛盾，应明确它不是可靠的剧情年龄。

## 物品信息

地图对象库存逐项列出类型、英文物品名、中文物品名和数量。库存为空时直接写明“地图对象库存为空”。

商人的交易库存如果由地图外容器提供，应与人物随身物品分开，并明确：

- 该容器是交易系统使用的库存；
- 容器位于正常地图边界之外；
- 不能把其中物品写成人物身上可直接取得的物品。

## 可以谈论的主题

只有脚本提供关键词询问时建立此节。表格格式固定为：

| 关键字 | 关键字实际的全名（中英文） | 内容 |
|---|---|---|

内容采用素材中的实际回答。同义关键字的实际主题相同，应相邻排列。

## 对话

### 整理顺序

1. 先确定首次交谈、再次交谈、中立、友好、敌对和低智力等入口。
2. 按人物实际相处阶段分组，而不是按脚本过程编号罗列。
3. 每个节点记录人物原话、玩家可见选项和选择后的下一分支。
4. 商店、战斗、移动地图、结束对话等结果使用清楚的文字标识。
5. 随机台词必须展开实际的消息范围；有状态条件时分组列出。
6. 脚本中没有调用入口的孤立台词不写成正常可触发对话。

对话表格推荐格式：

| 相处阶段或当前回应 | 玩家选项与分支 |
|---|---|

人物原话和玩家选项采用当前中文素材；为帮助阅读而添加的“初次交谈”“结束对话”等只是分支说明，不能改写成游戏台词。

## 叙事内容

### 身份与处境

只写地图位置、职业、组织关系、当前生活状态和可直接确认的人际关系。

### 生平

按时间顺序整理人物自己讲述的经历。叙述前说明来源；人物明确表示记不清或不确定的内容必须保留这种不确定性。

### 他人评价

每条评价注明说话者。其他人物的判断不能直接替代人物自述。

评价表中的人物必须链接到实际人物笔记。Markdown 表格内使用别名双链时，竖线必须转义，例如 `[[Hub 哈勃城 - Beth 贝斯（ID 2128）\|Beth 贝斯]]`；正文段落中则仍使用未转义的 `|`。

### 掌握的信息

保留“亲眼见过”“自己判断”“听说”和“传闻”的区别。人物把某项内容说成听闻时，笔记不得将其写成已确认机制。

### 任务关联

说明人物是否为任务发起人、信息来源、目标、敌人或带路者。不是任务最初发起人时，不因其在中间环节重要而误写成发起人。

任务表中的任务名和人物名都应链接到实际文件；表格内的别名分隔符同样写成 `\|`。完成后同时检查目标文件存在和表格列数，防止未转义的竖线把一个双链拆成两列。

## 旧城区执行范围

旧城区使用 `HUBOLDTN / elevation 0` 的 30 个地图人物对象为清单：8 个专名或具名原型人物，22 个普通人物。`Rutger 罗格尔（ID 1124）`和`Vinnie 维尼（ID 1303）`虽然在该地图执行共用绑匪脚本，仍按各自人物原型保留姓名，同时说明其在旧城区的实际作用。

### 自动生成入口

资源仓库中的 `scripts/generate_old_town_character_notes.py` 固化了旧城区的人物对象清单、人物位置图、地图精灵、游戏数据、库存和脚本对话提取方式。重新生成时必须显式给出知识库根目录，并使用 `--overwrite` 才会覆盖已有页面；哈罗德页面由脚本固定跳过，避免覆盖已经人工整理的完整内容。

```text
uv run --frozen python scripts/generate_old_town_character_notes.py \
  --vault-root <辐射1知识库根目录> \
  --overwrite
```

### 2026-07-31 执行结果

- 旧城区 30 个地图人物对象均有独立笔记，地图对象 ID 无缺失、无重复。
- 保留哈罗德现有完整页面；重写其余 27 篇旧页面，并新建罗格尔（ID 1124）和维尼（ID 1303）两篇页面。
- 为 29 篇重建页面分别生成一张人物位置图。
- 导出 26 张与对象 FRM、朝向一致的地图人物精灵。三个男孩对象使用的 `NACHLDAA.FRM` 当前没有可用导出帧，因此三篇页面明确记录缺失，不借用其他造型。
- 旧城区使用到的所有人物原型 `head_fid` 均为 `-1`；除已经另行从对话资源确认的哈罗德外，其余页面不添加独立对话头像。
- 旧城区总页中的罗格尔、维尼及其随身物品已经改为指向带地图对象 ID 的旧城区人物页面；中心区的罗格尔任务发起人链接保持不变。
- 批量重建前版本保存在 `工程/知识库整理/备份/2026-07-31-旧城区人物文档统一重建前.zip`。

## 验收清单

- [ ] 文件名、标题和属性中的地图对象 ID 一致。
- [ ] 地图、楼层、地图格、坐标和朝向来自同一个地图对象。
- [ ] 专名有脚本、原型或直接台词依据。
- [ ] 没有给素材未提供姓氏的人补姓。
- [ ] 普通同名人物逐对象建页，没有合并数量。
- [ ] 位置图按对象 ID 高亮，普通人物绿色、当前人物橙色。
- [ ] 地图精灵使用实际 FRM、实际朝向和第0帧。
- [ ] 没有独立对话头像时没有借用头像。
- [ ] SPECIAL、战斗数据和库存与原型、地图对象一致。
- [ ] 交易库存与随身库存分开。
- [ ] 对话选项和分支均可在脚本消息引用中追溯。
- [ ] 随机台词范围已展开，孤立不可达台词未混入主流程。
- [ ] 人物自述、他人评价、传闻和推断已经区分。
- [ ] 修改后的图片嵌入和内部链接可以在 Obsidian 中显示。
