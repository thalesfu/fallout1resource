# 命名规范与资源来源优先级

## 核心原则

资料页名称以当前本机游戏资源中能够追溯的中英文显示名为准，不依据攻略标题、记忆或内部文件名自行翻译。

人物存在完整姓名时，一律使用完整姓名。只有名字、姓氏或称号时，不推测缺失部分。

## 资源来源优先级

### 一级：游戏实际显示文本

1. 原版英文 `MASTER.DAT` 中的英文 MSG。
2. 本机松散 `DATA/TEXT/ENGLISH/` 中的 GBK 汉化覆盖。
3. 同一编号重复出现时，以转换结果中 `effective: true` 的最后一项为游戏实际生效文本。

主要转换结果位于：

```text
/Users/thalesfu/codes/github.com/thalesfu/fallout1resource/workspace/output/text/
```

人物优先检查 `DIALOG/*.json` 中的相遇描述、自我介绍和他人明确提及；地点优先检查 `GAME/MAP.json`；通用人物与物品优先检查 `GAME/PRO_CRIT.json`、`GAME/PRO_ITEM.json` 和 `GAME/SCRNAME.json`。

### 二级：对象身份链路

使用以下链路确认页面对应的是哪个游戏对象：

```text
MAP 对象 → script_filename → INT / MSG → PRO_CRIT 或 PRO_ITEM
```

地图渲染元数据位于：

```text
/Users/thalesfu/codes/github.com/thalesfu/fallout1resource/workspace/output/maps-rendered/
```

`HIGHTOWR.INT`、`HUBOLDTN.MAP` 等内部文件名只作为身份和来源证据，不直接充当读者可见名称。

### 三级：人工译名配置

`fallout1resource/config/*names.zh-CN.json` 用于地图标注，是可追溯的人工配置，但不是原始游戏文本。若配置与实际生效 MSG 或 GAME 文本冲突，以实际生效文本为准，并记录配置需要修正。

已发现的实例：哈勃城配置曾写作“达伦特·海托”，而汉化 `HIGHTOWR.MSG`、`PRO_CRIT.MSG` 和多处对话实际采用“达伦·海托”。知识库应使用后者。

### 四级：截图与现有笔记

截图用于确认玩家实际看到的对象和位置。现有笔记只作为匹配线索，不能覆盖更直接的资源证据。

## 人物文件名格式

有专名人物：

```text
地点英文名 中文名 - 英文完整姓名 中文完整姓名.md
```

例如：

```text
Hub 哈勃城 - Butch Harris 布奇·哈里斯.md
Hub 哈勃城 - Daren Hightower 达伦·海托.md
Hub 哈勃城 - Justin Greene 贾斯丁·格林.md
Junktown 迦克镇 - Killian Darkwater 基利安·达克沃特.md
```

无专名人物：

```text
地点英文名 中文名 - 英文资源称呼 中文资源称呼（必要的区域或组织消歧）.md
```

称号、职业、组织和任务身份通常写入正文属性，不塞入专名人物的文件名。只有无专名人物或重名人物才使用全角括号消歧。

## 全名判断规则

- 自我介绍出现完整姓名：采用完整姓名。
- 其他角色、告示或任务文本明确出现完整姓名：可以采用，但至少保留一处可追溯证据。
- `PRO_CRIT.MSG` 给出完整姓名：可以直接采用。
- 只有内部脚本缩写暗示姓氏：不能据此补全。
- `Doctor`、`Sheriff`、`Deputy`、`Mrs.` 等称号不等同于名字，但若资源始终将其作为固定显示名的一部分，可以保留。
- `Doc Morbid` 属于资源中的固定称号式姓名；没有证据时不扩写为其他姓名。

## 中英文书写

- 英文姓名保持资源中的大小写和“名 + 姓”顺序。
- 中文完整姓名使用汉化实际出现的译法。
- 中文姓名内部统一使用间隔号 `·`，不使用英文句点 `.`。
- 中英文名称之间保留一个半角空格。
- 文件名中的补充说明使用全角括号。

## 别名

重命名后，将旧名称、简称和确有资源依据的其他译法写入 `aliases`。别名用于搜索和兼容旧称，不与规范名竞争。

示例：

```yaml
---
aliases:
  - Harris Butch 布里奇
  - Butch 布奇
resource_map: HUBDWNTN.MAP
resource_script: BUTCH.INT
resource_dialog: BUTCH.MSG
---
```

## 冲突处理

无法确认时不重命名，审计状态标记为“待确认”。至少核对：

1. 当前页面截图中的对象位置和外观。
2. 对应 MAP 对象的 `script_filename`。
3. 同名 MSG 的相遇描述或自我介绍。
4. 汉化有效文本与原版英文文本是否确实对应同一编号。
5. 是否与其他现有页面记录了同一对象或同一段对话。
